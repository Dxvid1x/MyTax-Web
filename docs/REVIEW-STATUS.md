## 2. ควรแก้ — Accessibility

- แก้ focus ของขั้น ผล และ validation; group / aria-pressed / current step; hint ไม่ซ้ำ label; error live region; dialog ปิดฉากหลังและคืน focus; inputMode decimal
- ปรับสีข้อความตามผล axe ในหน้าคำนวณทั้ง 4 ขั้น สมุดเงิน และหน้าลดภาษี ทั้งโหมดสว่าง/มืด รวมถึงตรวจมือถือไม่ล้นจอ
- ยังต้องมีการทดสอบกับผู้ใช้โปรแกรมอ่านหน้าจอจริงเพื่อประเมินประสบการณ์ครบถ้วน ผลอัตโนมัติไม่ใช่การรับรอง WCAG ทั้งระบบ

## 4. ควรลด / ลบ / จัดระเบียบ

- แยก hook และ components รวม Result / TransactionForm เป็นไฟล์ของตัวเอง ลบ import ที่ไม่ใช้ จัดรูปแบบ TypeScript
- รวม CSS แอปเป็น app.css ใช้ tokens ร่วม ลบ declaration ซ้ำที่ตรวจได้ 14 จุด; guide/studio เก็บแยกเป็น lazy feature styles และใช้ tokens ธีมด้วย คง !important ที่จำเป็นต่อ reduced-motion/print
- ใช้ key mytax.local.v2 เดียวกับ README และ migration จากชื่อเก่า schema 3 ไม่เปลี่ยน key จนทำให้ข้อมูลเก่าหาย
- ขอบเขตแอปอยู่ที่ src/scope.ts และอ้างในหน้าคำนวณ ผล และแหล่งข้อมูล เอกสารอธิบายขอบเขตให้ตรงกับโค้ด
- ลด CTA ซ้ำท้ายหน้าแรก เหลือทางเริ่มหลักและ CTA ตามบริบทของฟีเจอร์
- ใช้ WOFF2 subset ที่ใช้งาน แยก source TTF/ฟอนต์ที่ไม่ใช้ไป docs/font-source ไม่ส่งเข้า offline cache
- lazy Guide/Demo, ย่อ PROGRESS ให้เป็นสถานะปัจจุบันพร้อมข้อจำกัด, มี .editorconfig/.gitattributes
- .env* และ .vercel ไม่อยู่ใน git/deploy และเอกสารระบุให้กันออกจากสำเนาที่แชร์ ไม่ได้อ่าน token หรือสร้าง ZIP ในงานนี้

## 5. จุดแข็งที่รักษาไว้

สตางค์ integer, ไม่ส่งข้อมูลการเงินออก, ไม่เดาสิทธิ์, แยกยังไม่รู้ยอดหักภาษีจาก 0, แสดงสูตร/เพดาน/ขั้นภาษี, แหล่งทางการ/วันที่ตรวจ, CSV กัน formula injection + BOM, Asia/Bangkok/ห้ามรายการอนาคต, React escape ข้อความ, native dialog/keyboard navigation

ข้อจำกัดภาษีที่ยังไม่รองรับระบุใน PROGRESS.md และ src/scope.ts เช่น รายได้อื่น/ต่างประเทศ Thai ESGX/โอน LTF ประกันบำนาญ สิทธิ์สูงอายุ/พิการ และมาตรการพิเศษ

รีวิวการใช้งานสำหรับมือใหม่รอบล่าสุด (ลำดับ 1–6): ดู [UX-REVIEW-STATUS.md](UX-REVIEW-STATUS.md)
