# แผนเว็บแอปภาษีและการเงิน — MVP ภายใน 3 วัน

วันที่สรุป: 2026-10-03  
สถานะ: ขอบเขตที่ตกลงสำหรับเริ่มพัฒนา ยังไม่ใช่เว็บที่สร้างเสร็จ  
ชื่อชั่วคราว: MyTax — เปลี่ยนชื่อได้ก่อนเผยแพร่

## 1. ไอเดียและกลุ่มผู้ใช้

เว็บช่วยให้วัยทำงานเข้าใจภาษีของตัวเอง ทดลองใช้ค่าลดหย่อน และจดรายรับ–รายจ่ายเพื่อดูภาพรวมเงินในชีวิตประจำวัน

กลุ่มเป้าหมายระยะยาวคือวัยทำงานและผู้มีรายได้ที่ต้องประเมินภาษี ส่วนเครื่องคำนวณในรุ่นแรกจำกัดที่เงินเดือนและโบนัสจากการจ้างงานในประเทศไทย กรณีรายได้อื่น รายได้ต่างประเทศ ภาษีคู่สมรสแบบรวม และเงื่อนไขพิเศษยังไม่อยู่ในขอบเขต ต้องบอกข้อจำกัดก่อนให้ผู้ใช้กรอก ไม่แสดงผลเหมือนรองรับแล้ว

ผู้ใช้ที่มีรายได้หลายแบบยังใช้สมุดรายรับ–รายจ่ายได้ แต่ผลสรุปสมุดเงินไม่ใช่ผลคำนวณภาษี

เป้าหมาย: ผู้ใช้ใหม่คำนวณกรณีพื้นฐานได้โดยไม่สมัครสมาชิก และเพิ่มรายการเงินหนึ่งรายการได้อย่างรวดเร็ว

## 2. ข้อสรุปที่ตกลงแล้ว

- ทำระบบภาษีเป็นส่วนหลัก ตรวจสอบให้เสร็จก่อนส่วนสมุดเงิน
- เพิ่มสมุดรายรับ–รายจ่ายแบบง่าย พร้อมสรุปสัปดาห์และเดือนในหน้าเดียว
- ไม่มีบัญชีผู้ใช้และการซิงก์ออนไลน์ในรุ่นแรก
- บันทึกในเครื่องเมื่อผู้ใช้เลือก เปิดเผยว่าข้อมูลอยู่ในเบราว์เซอร์/อุปกรณ์นี้
- ไม่เชื่อมรายการรายรับไปคำนวณภาษีอัตโนมัติ
- ทำหน้าจอให้ใช้ได้บนมือถือและคอมพิวเตอร์
- ใช้ภาพร่างเดิมเป็นแนวดีไซน์ ส่วนขอบเขตในเอกสารนี้มีผลเหนือภาพร่างเดิม

## 3. ขอบเขตฟีเจอร์

| ส่วน | สิ่งที่ต้องมี | ขอบเขตควบคุมเวลา |
|---|---|---|
| คำนวณภาษี | เลือกปี กรอกรายได้ทั้งปี โบนัส ภาษีหักไว้ และค่าลดหย่อน | รองรับกรณีเงินเดือนทั่วไปหนึ่งปีที่ตรวจหลักฐานครบก่อน; ไม่สัญญารองรับหลายปี |
| ค่าลดหย่อน | แบ่งหมวด คำอธิบาย เงื่อนไข เพดาน และรายการที่นำมาคิดได้จริง | เปิดเฉพาะรายการที่ตรวจปีและเงื่อนไขแล้ว |
| ผลภาษี | ภาษีโดยประมาณ ยอดจ่ายเพิ่ม/ขอคืน ขั้นตอนคำนวณ | ไม่มีการยื่นแบบหรือรับรองยอดคืนจริง |
| ทดลองปรับแผน | เปรียบเทียบค่าลดหย่อนปัจจุบันกับสถานการณ์สมมติ | ไม่มีแนะนำกองทุนรายตัวหรือซื้อผลิตภัณฑ์ |
| สมุดเงิน | เพิ่ม แก้ ลบรายรับ/รายจ่าย; วันที่ หมวด จำนวน หมายเหตุ | ไม่มีใบเสร็จ บัญชีหลายกระเป๋า หรือรายการเกิดซ้ำ |
| สรุปช่วงเวลา | รายรับรวม รายจ่ายรวม ผลต่าง และรายจ่ายแยกหมวด | หน้าสรุปเดียวสลับสัปดาห์/เดือน |
| บันทึก/ส่งออก | เลือกบันทึกในเครื่อง ล้างข้อมูล ส่งออกสมุดเงิน CSV และพิมพ์ผลภาษี | PDF ผ่านคำสั่งพิมพ์ของเบราว์เซอร์ ไม่ทำระบบสร้าง PDF แยก |

### รายการค่าลดหย่อนที่เสนอให้ตรวจเพื่อเปิดใช้ก่อน

ส่วนตัว ประกันสังคม ประกันชีวิต/สุขภาพ PVD และ RMF เป็นรายการเริ่มต้นที่เสนอ ต้องตรวจตามปี รวมเงื่อนไขและเพดานร่วมก่อนเปิดใช้ ไม่ใช่รายการที่รับรองว่าพร้อมใช้งานแล้ว

คู่สมรส บุตร บิดามารดา ดอกเบี้ยบ้าน เงินบริจาค Thai ESG และมาตรการชั่วคราวเพิ่มได้เฉพาะเมื่อมีเวลาตรวจและทดสอบครบ ไม่ใส่ช่องตัวเลขค่าลดหย่อนอิสระที่ข้ามการตรวจสิทธิ์ รายการที่ยังไม่รองรับต้องบอกให้ทราบก่อนคำนวณ หากผู้ใช้ต้องการนำรายการนั้นมาคิด ให้แจ้งว่ารุ่นนี้คำนวณกรณีของเขาได้ไม่ครบ

## 4. โครงสร้างหน้าและเส้นทางใช้งาน

เมนูหลัก: หน้าแรก / คำนวณภาษี / สมุดเงิน

### A. หน้าแรก

- หัวข้อ: **เข้าใจภาษี วางแผนเงิน**
- คำอธิบายสั้น: คำนวณภาษีเบื้องต้น ทดลองค่าลดหย่อน และติดตามรายรับ–รายจ่าย
- ปุ่มหลัก: เริ่มคำนวณภาษี
- ปุ่มรอง: จดรายรับ–รายจ่าย
- แสดงตัวอย่างแยกจากข้อมูลจริงอย่างชัดเจน ห้ามบันทึกตัวอย่างปนกับข้อมูลผู้ใช้
- ไม่บังคับลงทะเบียน

### B. เครื่องคำนวณภาษี — 3 ขั้นตอน

**ขั้น 1: ปีและรายได้**

- ปีภาษี พ.ศ./ค.ศ. พร้อมคำอธิบายว่าเป็นปีที่เกิดรายได้ ไม่ใช่ปีที่ยื่น
- ตรวจว่าผู้ใช้มีเฉพาะเงินเดือน/โบนัสในกรณีที่รองรับ หากไม่ใช่ให้แสดงขอบเขตและหยุดผลคำนวณสำหรับกรณีทั้งหมด
- เงินเดือนและค่าจ้างรวมทั้งปี **ก่อนหัก** ภาษีและเงินสมทบ
- โบนัสทั้งปี โดยบอกให้แยกจากยอดเงินเดือน ห้ามนับโบนัสซ้ำ
- ภาษีหัก ณ ที่จ่ายทั้งปี
- ตัวช่วยเงินเดือนต่อเดือน × จำนวนเดือนที่ได้รับ เป็นตัวเลือก; ค่ารวมทั้งปีเป็นยอดหลักเพียงชุดเดียว ไม่รวมทับกับตัวช่วย
- ถ้าประเมินปีที่ยังไม่จบ ให้ระบุว่ายอดทั้งปีเป็นประมาณการ

**ขั้น 2: ค่าลดหย่อน**

- แยกหมวดพร้อมข้อความอธิบายที่สั้นและเปิดรายละเอียดได้
- กรอกยอดที่จ่ายจริง ถามเงื่อนไขที่มีผลต่อสิทธิ์เฉพาะรายการที่เลือก
- แสดงยอดที่กรอก ยอดที่นำมาคิดจริง และเหตุผลเมื่อถูกจำกัดโดยเพดาน
- รายการที่คำนวณอัตโนมัติแสดงให้อ่านได้โดยไม่ต้องให้กรอกซ้ำ
- เพดานร่วมต้องคิดจากทุกช่องที่เกี่ยวข้อง ไม่ดูแต่ช่องใดช่องหนึ่ง

**ขั้น 3: ผลและทดลองปรับแผน**

- ตัวเลขเด่น: ภาษีทั้งปีโดยประมาณ / จ่ายเพิ่มหรือขอคืนโดยประมาณ
- แยกยอดภาษีหักไว้ให้เห็น ไม่เรียกภาษีทั้งปีว่าเป็นเงินที่ต้องจ่ายเพิ่ม
- เปิดรายละเอียด: รายได้รวม → ค่าใช้จ่ายตามกฎหมาย → ค่าลดหย่อน → เงินได้สุทธิ → ภาษีแต่ละขั้น → หักภาษีที่จ่ายไว้
- ไม่ใช้คำว่าเงินเหลือในบัญชีจากผลภาษี เพราะเครื่องคำนวณไม่ได้รู้รายจ่ายจริง
- ปีภาษี รุ่นกฎ วันที่ตรวจ และแหล่งอ้างอิงแสดงในส่วนผลลัพธ์
- แผงทดลองปรับแผนแสดงภาษีก่อน/หลัง ภาษีที่ประหยัด และเงินที่ต้องจ่ายเพิ่มแยกกัน
- ยอดสถานการณ์สมมติคือยอดรวมใหม่ของรายการนั้น ไม่เอาไปบวกยอดเดิมซ้ำ ใช้ตัวเลขกรอกแทนการทำ slider ซับซ้อนในรุ่นแรก
- สถานการณ์สมมติไม่เขียนทับแผนหลักจนกดนำไปใช้; ถ้าเปลี่ยนกฎหรือปีต้องคำนวณใหม่
- ปุ่มย้อนแก้ข้อมูลและปุ่มพิมพ์/บันทึก PDF

เส้นทาง: หน้าแรก → ปีและรายได้ → ค่าลดหย่อน → ผล → ทดลองปรับ → พิมพ์หรือบันทึก

### C. สมุดเงินและสรุป — หน้าเดียว

ส่วนบน: สลับสัปดาห์/เดือน เลือกช่วง และเลื่อนช่วงก่อนหน้า/ถัดไป

แสดงการ์ด 3 ใบ: รายรับรวม / รายจ่ายรวม / ผลต่างรายรับ–รายจ่าย

ผลต่างนับเฉพาะรายการในช่วงที่เลือก ไม่ใช่ยอดคงเหลือธนาคาร ไม่ยกยอดช่วงก่อนมาโดยอัตโนมัติ ถ้าติดลบแสดงว่า “รายจ่ายมากกว่ารายรับ”

ฟอร์มเพิ่มรายการ:

- ประเภท: รายรับหรือรายจ่าย
- จำนวน: มากกว่า 0 รองรับทศนิยมสองตำแหน่ง
- วันที่: ค่าเริ่มต้นวันนี้; รุ่นแรกใช้รายการที่เกิดขึ้นแล้ว ไม่รองรับรายการอนาคต
- หมวดรายรับ: เงินเดือน / งานเสริม / อื่น ๆ
- หมวดรายจ่าย: อาหาร / เดินทาง / ที่พัก / ช้อปปิ้ง / สุขภาพ / อื่น ๆ
- หมายเหตุ: ไม่บังคับ

ส่วนล่าง: รายจ่ายแยกหมวดด้วยแถบสัดส่วนเรียบง่าย และรายการย้อนหลังที่แก้/ลบได้

สัปดาห์เริ่มวันจันทร์และจบวันอาทิตย์ เดือนใช้เดือนปฏิทิน บอกวันเริ่ม–สิ้นสุดที่นับให้เห็น วันที่รายการเก็บแบบ YYYY-MM-DD ตามวันที่ผู้ใช้เลือก ไม่แปลงจนวันเลื่อนจาก timezone

ช่วงปัจจุบันสรุปรายการถึงวันนี้ ไม่คาดการณ์เงินเดือนทั้งเดือน เมื่อยังไม่มีข้อมูลให้แสดงคำแนะนำเริ่มเพิ่มรายการ

ข้อความใต้ฟอร์ม: “บันทึกเฉพาะรายรับหรือรายจ่ายจริง ไม่นับเงินย้ายระหว่างบัญชีตัวเอง”

เส้นทาง: เปิดสมุดเงิน → เพิ่มรายการ → ดูสรุป → สลับช่วงเวลา → แก้รายการหรือส่งออก

## 5. หลักคำนวณและตรวจข้อมูล

### ภาษี

- แยกฟังก์ชันคำนวณจากหน้าจอ และแยกข้อมูลกฎตามปี
- คิดภาษีตามช่วงเงินได้สุทธิ ไม่เอารายได้ทั้งหมดคูณอัตราสูงสุด
- ยอดจ่ายเพิ่ม/คืน = ภาษีที่คำนวณ − ภาษีที่หักไว้; ค่าเป็นลบแสดงยอดคืนโดยประมาณเป็นจำนวนบวก
- ภาษีที่ประหยัดจากค่าลดหย่อน = ภาษีก่อน − ภาษีหลัง โดยคำนวณทั้งสองสถานการณ์ใหม่ รองรับกรณีข้ามขั้นภาษี
- ค่าใช้จ่ายหักตามกฎหมายสำหรับรายได้และค่าลดหย่อนเป็นคนละส่วน ต้องแสดงแยกกัน
- ไม่ให้ยอดเกินเพดานถูกคิดเต็มโดยไม่มีคำอธิบาย
- ค่าว่างและค่าผิดรูปแบบต้องมีสถานะชัดเจน; ช่องจำเป็นที่ยังไม่กรอกไม่แสดงผลเหมือนคำนวณครบ
- ไม่ยืนยันว่าไม่มีหน้าที่ยื่นแบบเพียงเพราะผลภาษีเป็นศูนย์

### สมุดเงิน

- รวมรายการตามช่วงวันที่และประเภทอย่างเดียว ไม่โยงกับค่าภาษี
- เงินเก็บเป็นจำนวนสตางค์ชนิด integer; ปัด/แสดงผลอย่างสม่ำเสมอ
- แก้หรือลบแล้วสรุปใหม่ทันที ไม่เพิ่มยอดซ้ำเมื่อกดบันทึกติดกัน
- หมวดที่ไม่ใช้กับประเภทรายการต้องเปลี่ยนให้ถูกก่อนบันทึก
- CSV ส่งออกเฉพาะช่วงที่เลือก มีชื่อช่วงชัดเจน และป้องกันข้อความหมายเหตุถูกอ่านเป็นสูตรสเปรดชีต

## 6. ความถูกต้องของกฎภาษี

เริ่มจากปี 2569 / 2026 หากตรวจเอกสารที่เกี่ยวข้องครบ หากยังตรวจไม่ครบ ให้ใช้ปีที่ตรวจครบและระบุให้เห็น ห้ามแสดงตัวเลือกปีที่ยังคำนวณไม่ได้ราวกับพร้อมใช้

ใช้ Skill `thai-tax-investment-rules` ที่เตรียมไว้เป็นขั้นตอนค้นและตรวจข้อมูล เอกสารเดิมปี 2568 ใน Skill เป็นบริบท ไม่ใช่ตารางกฎที่รับรองปี 2569

กฎแต่ละรายการต้องมี: ปีภาษี ค่าหรือเงื่อนไข วันเริ่ม/สิ้นสุดที่ใช้ได้ เอกสารทางการและข้อที่เกี่ยวข้อง วันที่ตรวจ สถานะตรวจแล้ว และรุ่นข้อมูล

ตรวจจากเอกสารไทยของกรมสรรพากรตามปี รวมกฎหมาย/ประกาศที่มีผลบังคับใช้ และตรวจผลิตภัณฑ์กับ ก.ล.ต. เมื่อจำเป็น ไม่คัดลอกตัวเลขจากหน้า overview หรือข่าวที่ไม่ตรวจช่วงเวลาบังคับใช้

แหล่งค้นหลัก: [กรมสรรพากร](https://www.rd.go.th/), [ก.ล.ต.](https://www.sec.or.th/), [สำนักงานประกันสังคม](https://www.sso.go.th/)

หมายเหตุจากการตรวจ 2026-10-03: [หน้า PIT ภาษาอังกฤษ](https://www.rd.go.th/english/6045.html) ยังมีข้อความตารางสำหรับปี 2013–2014 จึงใช้เป็นภาพรวมเท่านั้น ไม่ใช้เป็นชุดตัวเลขปัจจุบันสำหรับเว็บนี้

กฎที่ยังตรวจไม่ครบต้องปิดการคำนวณส่วนนั้นและบอกข้อจำกัด ตัวเลขตัวอย่างต้องติดป้าย “ข้อมูลสาธิต” แยกจากการคำนวณจริง

## 7. ข้อมูลและการบันทึก

การตัดสินใจรุ่นแรก: ประมวลผลในเบราว์เซอร์ ไม่มี backend ไม่มีฐานข้อมูลออนไลน์

- ค่าเริ่มต้นข้อมูลอยู่ในหน่วยความจำระหว่างเปิดเว็บ จนเลือก “บันทึกในเครื่องนี้”
- อธิบายก่อนเลือก: ข้อมูลเก็บในเบราว์เซอร์นี้ ไม่ซิงก์ข้ามอุปกรณ์ คนที่ใช้โปรไฟล์เบราว์เซอร์เดียวกันอาจเปิดเห็น และล้างข้อมูลเบราว์เซอร์แล้วอาจหาย
- เมื่อปิดการบันทึก ให้ลบสำเนาที่บันทึกไว้ แต่คงข้อมูลระหว่างใช้งานครั้งนี้พร้อมแจ้งให้ทราบ
- ปุ่ม “ล้างข้อมูลทั้งหมด” ลบทั้งแผนภาษีและสมุดเงินหลังยืนยัน
- ไม่ส่งรายได้หรือหมายเหตุไป analytics/logs ภายนอก
- ถ้าบันทึกไม่สำเร็จ แจ้งผู้ใช้ ห้ามแสดงว่าบันทึกแล้ว
- ไฟล์ PDF/CSV ที่ดาวน์โหลดแล้วอยู่นอกการล้างข้อมูลในเว็บ ต้องบอกให้ชัด
- CSV เป็นการส่งออกอ่านได้ ยังไม่มีระบบนำเข้ากู้คืนในรุ่นแรก

โครงสร้างข้อมูลขั้นต่ำ:

| ชุดข้อมูล | ฟิลด์สำคัญ |
|---|---|
| taxPlan | taxYear, annualEmploymentIncome, annualBonus, withholding, deductions, ruleVersion |
| transaction | id, type, amountSatang, date, category, note, createdAt, updatedAt |
| preferences | storageOptIn, selectedPeriod |
| storageEnvelope | schemaVersion, savedAt, taxPlan, transactions, preferences |

ไม่เก็บ scenario ทดลองเป็นรายการรายจ่ายจริง และไม่เก็บเลขบัตรประชาชน เลขบัญชี หรือเอกสารภาษีส่วนบุคคล

## 8. แนวดีไซน์

ใช้แนวภาพที่ตกลงจาก hiwdo.com และภาพ wireframe เดิม: พื้นขาว กริดบาง ตัวหนังสือสีเข้ม หัวข้อใหญ่ ปุ่มแคปซูลและสีชมพูเน้นการกระทำ

- จัดข้อมูลสำคัญก่อน รายละเอียดกดเปิดได้
- ภาษาไทยสั้น ใช้คำว่า “ยอดก่อนหัก” “ภาษีที่หักไว้” “จ่ายเพิ่ม/ขอคืน” พร้อมตัวอย่างเมื่อจำเป็น
- บนคอมพิวเตอร์แบบฟอร์มอยู่ซ้าย สรุปอยู่ขวา; มือถือเรียงเป็นคอลัมน์เดียว
- ช่องต้องมี label คงอยู่ หน่วยบาท และข้อความผิดพลาดใต้ช่อง
- สีไม่ใช่สัญญาณเพียงอย่างเดียว ใช้ข้อความและเครื่องหมายประกอบ
- ปุ่มมีพื้นที่กดเหมาะกับมือถือ รองรับคีย์บอร์ดและ focus ที่มองเห็น
- ปิด motion ได้ตามการตั้งค่า reduced motion ไม่ทำแอนิเมชันที่กินเวลาพัฒนา
- ไม่ใช้ social proof จำนวนผู้ใช้ หรือคำรับรองที่ยังไม่มีหลักฐาน

## 9. แนวเทคนิคที่เสนอ

สำหรับผู้พัฒนาคนเดียวใน 3 วัน: React + TypeScript + Vite, CSS สำหรับหน้าจอ, localStorage แบบเลือกเปิด, ฟังก์ชันคำนวณแยก และชุดทดสอบ logic ที่สำคัญ

ใช้ dependency น้อย ไม่จำเป็นต้องมี backend หรือระบบ AI ในเว็บ การเลือกเวอร์ชันและบริการโฮสต์ตรวจตอนเริ่ม implementation; ถ้ามีโปรเจกต์เดิมให้ใช้โครงสร้างเดิมก่อน

พิมพ์ผลด้วย print stylesheet และ browser Save as PDF; CSV สร้างในเครื่อง ปล่อย static web ที่ใช้ HTTPS ได้เมื่อถึงขั้นเผยแพร่และผู้ใช้เลือกปลายทางแล้ว

## 10. แผน 3 วัน

ประมาณการนี้สมมติว่ามีผู้พัฒนาหนึ่งคนทำงานเต็มวัน มีเครื่องมือพร้อม และเอกสารกฎหาได้ เป็นเป้าหมายการทำงาน ไม่ใช่การรับประกันกำหนดเสร็จ

| วัน | งาน | ผลที่ต้องเห็น |
|---|---|---|
| 1 | ล็อกกรณี/ปีที่รองรับ ตรวจเอกสารกฎ วางโครงหน้า ทำ tax engine และทดสอบขั้นภาษี | คำนวณกรณีที่รองรับได้และมีหลักฐานกฎ พร้อมฟอร์มพื้นฐาน |
| 2 | เชื่อมฟอร์ม ผลละเอียด ทดลองค่าลดหย่อน หน้าแรก และรูปแบบพิมพ์; ทดสอบมือถือ | เส้นทางภาษีครบตั้งแต่กรอกจนพิมพ์ผล ไม่มีข้อผิดพลาดสำคัญ |
| 3 | เพิ่มสมุดเงิน สรุปสัปดาห์/เดือน การบันทึกและ CSV; ตรวจเส้นทางทั้งหมด | เว็บทดลองใช้ได้ตามเกณฑ์รับงานด้านล่าง |

Checkpoint สิ้นวันที่ 2: ถ้าภาษีหรือกฎยังไม่พร้อม ให้ใช้วันที่ 3 แก้ส่วนนี้ก่อน สมุดเงินเลื่อนออกได้ตามที่ตกลง ไม่เปิดเครื่องคำนวณกฎที่ยังไม่ตรวจเพื่อรักษากำหนดเวลา

ลำดับลดงานเมื่อเวลาไม่พอ: ลดความละเอียดภาพตกแต่ง → ตัดกราฟใช้ตัวเลข/ตาราง → จำกัดรายการค่าลดหย่อนที่ตรวจครบ → เลื่อนสมุดเงิน ห้ามลดความถูกต้อง การบอกขอบเขต หรือการควบคุมข้อมูล

## 11. เกณฑ์รับงาน

### ภาษี

- เลือกได้เฉพาะปีที่รองรับ เห็นขอบเขตก่อนกรอก และมีแหล่งกฎตรวจแล้ว
- คำนวณเงินเดือน/โบนัสโดยไม่ซ้ำ ค่าใช้จ่าย/ค่าลดหย่อนถูกแยก
- ทดสอบศูนย์ ขอบแต่ละขั้นภาษี ก่อน/หลังขอบ เพดานรายการและเพดานร่วม รวมกรณีภาษีหักไว้มาก/น้อยกว่าภาษี
- สถานการณ์ค่าลดหย่อนที่ข้ามขั้นภาษีคำนวณ savings ถูกต้องและแยก cash committed
- มีกรณีตัวอย่างคำนวณอิสระที่อิงเอกสารกฎเพื่อเทียบผล ไม่ใช้ตัว engine เดิมสร้าง expected values
- เปลี่ยน input แล้วผลและคำอธิบายเปลี่ยนสอดคล้อง; ย้อนหน้าข้อมูลไม่หาย
- เอกสารพิมพ์มีปี สมมติฐาน ขอบเขต รายละเอียดและแหล่งอ้างอิง

### สมุดเงิน

- เพิ่ม แก้ ลบ และรวมยอดใหม่ถูก; กดติดกันไม่เกิดรายการซ้ำ
- ทดสอบวันจันทร์/อาทิตย์ สิ้นเดือน ข้ามปี และเดือนกุมภาพันธ์ในปีอธิกสุรทิน
- ช่วงว่างแสดงศูนย์พร้อมคำแนะนำ ไม่เกิดกราฟผิดหรือ NaN
- ผลต่างรายรับ–รายจ่ายไม่เรียกเป็นยอดบัญชีธนาคาร และไม่ส่งเข้าคำนวณภาษี
- CSV ภาษาไทยอ่านได้ในโปรแกรมสเปรดชีต และหมายเหตุไม่กลายเป็นสูตร

### การใช้งานและข้อมูล

- ใช้บนมือถือขนาดเล็กได้ ไม่มีแนวนอนล้น และใช้คีย์บอร์ดกับฟอร์มได้
- ไม่เลือกบันทึกแล้วรีโหลดข้อมูลต้องไม่ค้างจาก session ก่อน
- เลือกบันทึกแล้วกลับมาอ่านได้; storage เสีย/เต็มแจ้งปัญหาอย่างชัดเจน
- ล้างข้อมูลแล้วไม่มีข้อมูลเดิมโหลดกลับมา และแสดงว่าต้องลบไฟล์ export เอง
- การคำนวณและบันทึกไม่ส่งข้อมูลการเงินออกจากอุปกรณ์

## 12. สิ่งที่เก็บไว้รุ่นถัดไป

บัญชีผู้ใช้และซิงก์, ฟรีแลนซ์/รายได้หลายประเภท, รายได้ต่างประเทศ, เป้าหมายออม/เกษียณ, งบรายหมวด, รายการเกิดซ้ำ, แจ้งเตือน, นำเข้ารายการ, สแกนใบเสร็จ, เชื่อมธนาคาร, AI แนะนำ และการยื่นภาษี
