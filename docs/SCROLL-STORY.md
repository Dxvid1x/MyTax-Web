# Homepage scroll story

Implemented 2026-10-03. The existing navigation, settings and layered Hero are preserved. The full interactive DemoStudio was removed from the homepage and its lazy bundle is no longer requested or precached. The demo source is retained as unused historical code; /demo still shows its existing static example result.

The story now uses “กรอกรายได้” → “เข้าใจภาษี” → “ง่ายแค่นี้เอง”, with the supplied descriptions and consistent opening/chapter/screen-reader labels; see LANGUAGE-UX.md. A single viewport stage stays pinned along the original long scroll track (310svh desktop / 300svh mobile). Native scrolling selects the scene and controls its crossfade, but no longer controls amount reveals or the RMF slider. Each scene plays its amounts independently when first seen: 1.4s for income, 1.4s for tax, 1.6s for the deduction trial. It then holds the completed values until the user scrolls to another scene. Waiting does not select another chapter.

Scrolling backward shows completed values without replaying them. If a started scene is left before finishing, its completion is recorded so returning immediately shows its final values. Completion is held in memory for the page load, including navigation to another tool and back; a refresh starts a new viewing session. There are no playback/restart buttons. The three original chapter buttons still scroll to their respective scenes; they do not reset animation. Nothing intercepts wheel, touch, keyboard scrolling or browser history.

The closing section says “ง่ายแบบนี้… ต้องเลือก MyTax” with a real “คำนวณของฉัน” button. The preserved Hero and its calculator/ledger buttons are now below the story; see HOMEPAGE-OPENING.md.

The graphic uses HTML/SVG icons and readonly visual fields, not editable sample inputs. All example calculations use the existing demoPlan/calculate functions. Year 2568 income is 660,000 baht, annual tax 20,100. Replacing RMF total 30,000 with 60,000 results in 17,100 tax and 3,000 savings, alongside the explicit 30,000 extra expenditure and RMF eligibility condition. This is not the user's plan and never mutates saved data.

Scene selection is measured by a passive scroll listener. Amount animation uses elapsed time with requestAnimationFrame and runs only for the selected, unfinished scene while the stage is visible. It pauses while the document is hidden. The component cleans up listeners, observers and pending frames when unmounted. Reduced motion or a short usable viewport retains the original normal static sequence with all three steps visible. Sticky-header measurement and progress offsets still apply. Preference changes respond without reload. The graphics have a static screen-reader description rather than announcing every animated amount.

Sources: src/ScrollStory.tsx, src/story.css and Home in src/main.tsx. No tax-rule, ledger, persistence or routing implementation changed.

QA: desktop dark, 390px and 320px screenshots under output/playwright/story-*.png. The original QA observed sticky position at top 0 (now offset below the homepage header; see NAVIGATION-MOTION.md), chapter selection reached all steps, reverse navigation restored chapter 0, static mode showed three relative-position scenes at opacity 1, and the final CTA navigated to /tax. Existing browser regressions ultimately passed: 24 passed in the first 27-test run; the three failed cases passed after a cursor contrast fix and an explicit main-navigation test selector. Their rerun took 19.4s and included production offline behavior. Formatting, ESLint/TypeScript and production build passed. Human usability testing remains pending.
